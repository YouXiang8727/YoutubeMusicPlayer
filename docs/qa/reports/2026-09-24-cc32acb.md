## 5. 風險觀察

1. **佇列 LazyColumn 區域內的下拖觸發捲動而非收起**（已知設計取捨，非缺陷）：bottom sheet 慣例——拖曳手勢起點在可捲動內容上時，優先捲動內容；僅 handle 區／面板空白區下拖才收起。預期行為，不列缺陷。
2. **Snackbar（播放失敗提示）於展開時會被遮罩蓋住**（低機率邊角）：展開 sheet 期間若觸發播放失敗 snackbar，其被 scrim 覆蓋不可見，收起後 snackbar 生命週期可能已結束。播放失敗通常在點擊卡片起播時發生（此時 sheet 為收斂態，snackbar 正常顯示），展開期間失敗僅存於佇列操作觸發的切歌失敗等低頻情境。**非阻斷**，登記風險觀察；若後續實測頻繁出現再議 UI 疊層（snackbar 提高 z-order／改為展開態內嵌提示）。
3. **環境教訓（與 android-mcp 並存）**：本 session 執行 `adb shell uiautomator dump` 會**癱瘓 android-mcp 的 Snapshot 能力**（需 reboot 模擬器才恢復）。與 android-mcp 並存時一律改用 MCP `Snapshot`／`ClickBySelector` 操作、禁用 uidump。此條僅記錄於本報告；runbook 更新屬 A 治理範疇，另議。
